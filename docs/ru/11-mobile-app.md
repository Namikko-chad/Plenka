# Мобильное приложение

`app/` — клиент на Flutter (пакет `plenka`) для Android-телефонов и ТВ-приставок и для
Linux. Работает только с plenka-server и играет видео нативным плеером (media_kit /
libmpv), поэтому справляется с MKV, AC3, DTS и встроенными субтитрами, которые не умеет
браузер.

Стек: flutter_bloc (cubit), go_router, get_it, dio, shared_preferences, media_kit,
android_intent_plus. Проверка: `flutter analyze` (без замечаний) и `flutter test`.

## Поиск сервера

Приложение принимает только серверы, у которых `GET /api/info` отвечает
`service == "plenka-server"`.

**Сервер, заданный вручную** (экран подключения или Настройки → Сменить сервер),
закрепляется (`server_manual`): при запуске приложение опрашивает только его — три попытки
с паузой 2 с и длинными таймаутами (соединение 6 с, ответ 8 с), потому что сеть ТВ
поднимается не сразу, а удалённый сервер отвечает медленно. Если он так и не ответил,
экран подключения называет его адрес и предлагает «Повторить», «Искать автоматически» и
другой адрес; автопоиск его не заменяет. Настройки → «Найти сервер автоматически» снимает
закрепление.

**Иначе** опрашивается адрес из сборки `SERVER_URL`, затем последний найденный `server_url`
(с длинными таймаутами), затем параллельно:

- UDP-broadcast `plenka-server:discover` на `255.255.255.255` и `x.y.z.255` каждой
  локальной IPv4-сети, порт 8095 (отправляется дважды, ответы собираются 2,5 с); ответ
  даёт адрес сервера (IP отправителя + `port` из JSON), который затем проверяется через
  `/api/info` — так находится сервер на любом адресе сети, например на компьютере;
- `x.y.z.1:8095` для каждой локальной IPv4-сети, `192.168.88.1`, `10.77.0.2`, `10.0.2.2`
  и `127.0.0.1`.

Побеждает первый ответивший сервер, он сохраняется как `server_url`. Если никто не ответил,
экран подключения позволяет ввести адрес вручную.

Адреса: `192.168.88.1` → `http://192.168.88.1:8095`; со схемой и без порта
(`https://kino.example.com`) остаётся стандартный порт схемы — для сервера за прокси.

Параметры сборки (`--dart-define`): `SERVER_URL`, `SERVER_PORT` (по умолчанию 8095).

## Структура каталогов

```
lib/
  l10n/          app_en.arb, app_ru.arb → сгенерированный AppLocalizations (flutter gen-l10n)
  core/          config (dart-define), di (get_it), theme (дизайн-токены), utils (форматы, естественная сортировка)
  data/server/   поиск сервера + ServerClient (общий Dio, абсолютные URL для плеера и картинок)
  data/api/      tmdb_api, search_api (/api/search), torrent_api (/api/torrents, ссылки /api/stream), history_api,
                 config_api (/api/config), indexers_api (/api/indexers, /api/definitions), engine_api (/api/engine/settings)
  data/models/   media, torrent, watch_entry, server_settings
  data/storage/  settings_store (адрес сервера и закреплён ли он, режим плеера, видеовыход, язык), history_store (локальная копия + синхронизация)
  presentation/  connect, shell (вкладки / боковая навигация), home, search, details, trailers, releases (раздачи),
                 torrents (вкладка «Торренты» и карточка торрента), files, player, settings, server_settings (трекеры, трекер, каталог, движок), общие виджеты, router
```

## Сценарии

- **Раздачи:** параллельно ищет `"{название} {год}"` и `"{оригинальное название} {год}"`
  (год только для фильмов), объединяет по infoHash или название+размер, сортирует по
  сидам. Показывает, сколько трекеров ответило и какие нет; если включённых трекеров нет,
  отправляет на `{сервер}/indexers`. Предпочитается `magnet`; иначе `link` (возможно,
  относительная ссылка скачивания трекера) передаётся движку как есть.
- **Добавление торрента:** `POST /api/torrents` с `{link, title, poster, data}` (карточка
  фильма JSON-строкой в `data`; сервер всегда сохраняет торрент); затем приложение раз в
  секунду опрашивает `GET /api/torrents/{hash}`, пока `files` не станет непустым (404 сразу
  после добавления повторяется; через 90 с — ошибка).
- **Плеер:** ссылка на поток `{сервер}/api/stream/{hash}/{fileId}/{имя файла в URL-кодировке}`
  (номера файлов с 1; имя нужно только плееру);
  режимы встроенный, внешний (Android intent) или «спрашивать». Во встроенном плеере выбор
  аудио и субтитров показывает дорожки самого файла и отдельные файлы раздачи: субтитры
  (`srt`, `ass`, `ssa`, `vtt`, `sub`) и аудио (`mka`, `ac3`, `eac3`, `dts`, `aac`, `flac`,
  `mp3`, `m4a`, `opus`, `ogg`, `wav`); отдельный файл добавляется в libmpv только при выборе.
  Файлы с именем видео идут первыми; на кнопках виден текущий выбор. Сетевой таймаут libmpv
  поднят с 5 с (умолчание media_kit) до 90 с: первый байт может идти долго, пока сервер
  загружает сохранённый торрент обратно в движок.
- **Видеовыход (Android):** Настройки → «Видеовыход». «Аппаратный — MediaCodec» (по
  умолчанию) рисует через `vo=mediacodec_embed`, `hwdec=mediacodec` и показывает HEVC 10 бит,
  HDR10+ и Dolby Vision, которые путь OpenGL выводит чёрным экраном; «Совместимый — OpenGL»
  оставляет умолчания media_kit (`vo=gpu`, `hwdec=auto-safe`). После ошибки воспроизведения
  в аппаратном режиме плеер один раз предлагает совместимый. На Linux всегда умолчания.
- **Смотреть → Торренты / Трейлеры:** кнопка «Смотреть» в карточке спрашивает, что смотреть.
  Трейлеры (`/trailers/{type}/{id}`) — видео YouTube из TMDB `/videos` (язык каталога, затем
  `en-US`; сначала трейлеры, новые выше); видео открывается в YouTube (Android-intent
  `VIEW`, на Linux `xdg-open`).
- **Файлы и предзагрузка:** у каждой раздачи есть кнопка «Файлы», открывающая список в режиме
  просмотра (все файлы, не-видео приглушены, ничего не запускается само); нажатие на раздачу
  по-прежнему запускает единственное видео. У каждого видео есть кнопка «Предзагрузить»
  (`POST /api/torrents/{hash}/preload`); пока `stat` равен 2, экран показывает прогресс
  (предзагрузка ложится на диск сервера). Кнопка в шапке загружает всю раздачу и держит её
  на диске сервера
  (`POST`/`DELETE /api/torrents/{hash}/download`, `507` → «не поместится»); экран показывает
  «Целиком: X / Y».
- **Вкладка «Торренты»** (`/torrents`, между «Поиском» и «Настройками», как вкладка
  «Торренты» в веб-интерфейсе): все торренты, сохранённые в движке сервера
  (`GET /api/torrents`, опрос раз в 3 с, пока вкладка открыта; обновление жестом вниз).
  Карточка показывает постер, название, статус движка, размер, значок загрузки целиком,
  скорость и пиров загруженного торрента и полосу прогресса идущей предзагрузки или
  загрузки целиком. Кнопки карточки: «Файлы» (список файлов в режиме просмотра, ничего не
  запускается само), «Выгрузить из памяти» (`POST /api/torrents/{hash}/drop`, только для
  загруженного торрента) и «Удалить» (`DELETE /api/torrents/{hash}`, после подтверждения).
  **«Добавить»** принимает magnet, ссылку на `.torrent` или хеш и необязательное название
  (`POST /api/torrents`); загрузки `.torrent`-файла в приложении нет. Нажатие на карточку
  открывает подробности (`/torrent`): статистика (статус, размер, загружено, скорости,
  пиры, сиды, прогресс загрузки целиком и предзагрузки, время добавления в часовом поясе
  устройства, хеш — нажатием копируется), карта кэша (`GET /api/torrents/{hash}/cache`;
  загружено, частично, в очереди, читается) и кнопки «Файлы», «Предзагрузка» (последний
  просмотренный файл этого торрента, иначе первое видео), «Загрузить целиком» / «Отменить
  загрузку» и «Удалить»; торрент и его кэш опрашиваются раз в 2 с.
- **История просмотров:** хранится на сервере (`/api/history`) с локальной копией, поэтому
  главная появляется сразу и работает без связи. Сохранение идёт сначала локально; запись
  в сеть выполняется в фоне, а неудачные записи ждут в сохраняемой очереди. Синхронизация
  — при подключении, открытии главной и обновлении жестом: побеждает более новый
  `updatedAt`, удалённые на сервере записи убираются локально, старая локальная история
  один раз выгружается на сервер.
- **Язык:** английский и русский. Тексты лежат в `lib/l10n/app_*.arb` (шаблон —
  английский); виджеты берут их через `context.l10n`, код без `BuildContext` (тексты
  ошибок, единицы размера, запросы к TMDB) — через глобальный `tr`. По умолчанию
  приложение следует языку устройства, а если он не поддержан — английскому; Настройки →
  Язык переключает «Язык устройства», English и Русский (сохраняется как `app_language`).
  Запросы к TMDB передают `language` по языку интерфейса (`en-US` / `ru-RU`); отдельно
  язык каталога не задаётся.
- **Пульт ТВ:** каждая вкладка живёт во вложенном навигаторе со своей областью фокуса,
  и стрелки останавливаются на её краю; каркас перехватывает «влево», которому внутри
  вкладки некуда идти, и переводит фокус на текущий пункт бокового меню. «Вправо» из
  меню возвращает во вкладку. Вверх/вниз всегда переводят фокус, в том числе из поля
  ввода (Flutter двигал бы в нём курсор, и с поля формы было бы не уйти); многострочных
  полей в приложении нет.
- **Настройки:** адрес и версия сервера, задан ли он вручную или найден; «Сменить
  сервер»; «Найти сервер автоматически»; состояние торрентов, трекеров («включено N из M»)
  и TMDB; язык интерфейса и режим плеера. **Настройки сервера** меняются в самом
  приложении, без перехода в веб-интерфейс:
  - *Трекеры* (`/server/indexers`): состояние и обновление определений, поиск и фильтр
    (все / включённые / публичные / приватные), переключатель у каждого трекера
    (включение трекера, которому нужен логин, открывает его настройки). Экран трекера
    (`/server/indexers/{id}`): включение, адрес сайта (один из `links` или свой), все поля
    определения (текст, пароль, флажок, список, множественный выбор; HTML из `info`
    показывается текстом) и «Проверить», которая сначала сохраняет форму. Значения
    отправляются в том виде, в каком их прислал сервер; пустой пароль оставляет прежний.
  - *Каталог и поиск* (`/server/catalog`): ключ TMDB (задать, заменить, удалить),
    таймаут поиска по трекерам, адрес FlareSolverr.
  - *Торрент-движок* (`/server/engine`): кэш (МБ), упреждающее чтение, предзагрузка,
    лимиты, порты, ретрекеры, папка для загрузок (видна всегда), кэш на диске, переключатели протоколов; «Сбросить по
    умолчанию». Обратно отправляется весь объект, поэтому неизвестные приложению поля
    сохраняются.
