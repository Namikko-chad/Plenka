# Торрент-движок

`backend/internal/torrserver/` — торрент-движок. Он основан на
[TorrServer MatriX](https://github.com/YouROK/TorrServer) (GPL-3.0) и доработан для
Plenka. Оставлен только движок; HTTP API поверх него — наш собственный, в
`backend/internal/torrents/` (`/api/torrents`, `/api/stream`, `/api/engine/settings`, см.
[REST API](31-rest-api.md) §1.8–1.10). Маршрутов, совместимых с TorrServer, нет.

## Пакеты

| Пакет | Назначение |
|---|---|
| `torrserver/torr/` | `BTServer` (настройка клиента anacrolix), `Torrent` (спецификация, статус, скорость, отключение простаивающих), предзагрузка, `Stream` (отдача по HTTP с Range), фасад API (`AddTorrent`, `FindTorrent`, `ListTorrent`, `RemTorrent`, `DropTorrent`, `SetSettings`, …) |
| `torrserver/torr/storage/torrstor/` | кэш кусков в памяти или на диске: `Cache` на каждый торрент, ридеры с окном упреждающего чтения, вытеснение кусков вне окон ридеров |
| `torrserver/settings/` | настройки движка `BTSets` и хранилище bbolt `config.db` (настройки, сохранённые торренты) |
| `torrserver/log/`, `torrserver/utils/`, `torrserver/mimetype/` | журнал, сортировка имён и определение типов медиа |
| `torrents/` | нативный HTTP API: разбор ссылок, JSON торрента, кэша и настроек, плейлисты, стриминг |

`FindTorrent` возвращает загруженный торрент или его сохранённую копию (`stat` 5), не
загружая его; список файлов сохранённого торрента берётся из сохранённых метаданных.
Стримы и плейлисты загружают сохранённый торрент по требованию и ждут метаданные до 60 с
(иначе `504`).

## Хранилище

`config.db` (bbolt, в `DATA_DIR`) содержит два бакета: `Settings` (ключ `BitTorr`, JSON
`BTSets`) и `Torrents` (по записи JSON на сохранённый торрент: спецификация с
метаданными, название, постер, клиентские `data`, время добавления, размер). При запуске
данные старых сборок переносятся: `settings.json` (где раньше по умолчанию лежали
настройки) копируется в `config.db` и удаляется; неиспользуемые бакет `Viewed` и
`viewed.json` удаляются. Сохранённые торренты остаются как есть. Файлы `trackers.txt` и
`blocklist` в каталоге данных по-прежнему читаются, если есть.

## Настройки

API отдаёт поля из §1.10 (camelCase). `PUT` приводит значения вне диапазона к границам,
сохраняет их и перезапускает BitTorrent-клиент (загруженные торренты сбрасываются и
переподключаются при следующем запросе); `DELETE` сохраняет и применяет значения по
умолчанию. Поля списка трекеров (`TrackersListURL`, `DefaultTrackers`) и локальный поиск
пиров (`EnableLPD`, `LPDIPv6`) работают со значениями по умолчанию, но не отдаются в API.

По умолчанию: кэш 64 МБ в памяти, упреждающее чтение 95 %, предзагрузка 50 %,
25 соединений на торрент, простаивающие торренты отключаются через 30 с.

**Кэш и сохранённые куски.** Кэш (`cacheSize`, в памяти или на диске при `useDisk`) держит
только окно вокруг позиции воспроизведения и вытесняет остальное. Предзагрузка и загрузка
целиком его не используют: их куски *сохраняются* на диск всегда, независимо от `useDisk`,
в `<torrentsSavePath>/<hash>/keep/` (пустой `torrentsSavePath` → `DATA_DIR/torrents`). Кусок
пишется в `<id>.part` и переименовывается в `<id>`, когда клиент его проверил; при загрузке
торрента кэш снова находит сохранённые куски. Они не входят в `cacheSize` и не вытесняются;
их не удаляют ни выгрузка по простою, ни `removeCacheOnDrop` — только удаление торрента
(или отмена загрузки целиком, см. ниже). Кусок, который уже был в кэше, переносится на диск
вместе с данными. Нужные сохранённые куски держат свой приоритет (`Normal`, `High` для
предзагружаемого файла), что бы ни делали окна чтения; сторож каждые 5 с его восстанавливает.

**Предзагрузка** (`POST /api/torrents/{hash}/preload`, `Torrent.Preload`) качает первые
`preloadCache` % **каждого** файла и его последние 8/16 МБ (индекс контейнера), выбранный
файл первым: при 50 % от файла 16 ГБ на диск ложится 8 ГБ, а кэш 64 МБ следует за
воспроизведением. Пока всё не скачано или торрент не закрыт, он в состоянии предзагрузки
(`stat` 2, не отключается по простою); `preloadedBytes` / `preloadSize` считают
сохранённые куски. `preloadCache` 0 выключает предзагрузку.

**Загрузка целиком** (`POST /api/torrents/{hash}/download`) сохраняет так же все куски, а
`Torrent.expired` не учитывает таймаут простоя. Отмена удаляет скачанные ею куски, кроме
сохранённых до её начала и запрошенных предзагрузкой, и снова включает таймаут простоя. Оба
обработчика отказывают (`507`), если не хватает места на диске под каталогом сохранения (с
учётом того, что ещё докачивают другие предзагрузки и загрузки целиком, плюс запас 512 МБ).
На роутере с небольшим объёмом памяти держите кэш в пределах 64–128 МБ, а
`torrentsSavePath` — на USB/NVMe-накопителе.

## Ссылки скачивания трекеров

У результатов поиска без magnet поле `link` имеет вид
`/api/indexers/{id}/download?token=…`. `POST /api/torrents` распознаёт такой путь
(относительный или абсолютный с любым хостом) и вызывает `torrents.IndexerLinkResolver`
(в `main.go` ему присваивается `ResolveLink` менеджера индексаторов), который при
необходимости входит на трекер и возвращает либо байты `.torrent`, либо magnet. Другие
принимаемые ссылки: magnet, http(s)-адрес `.torrent`, infohash в hex или base32.

## Что убрано из TorrServer

HTTP API TorrServer (`/echo`, `/torrents`, `/stream`, `/play`, `/playlist*`, `/viewed`,
`/cache`, `/settings`, `/torrent/upload`, `/ffp`) и его веб-страницы, DLNA, Bonjour,
GStreamer, FUSE/WebDAV, Telegram-бот, MCP, MSX, поиск rutor и клиент Torznab (их заменяет
`internal/indexers`), настройки TMDB, HTTPS/SSL и WAF, ffprobe, отметки просмотра, ссылки
torrshash, категории, ссылки `file://`, JSON-хранилище настроек и его миграции, режим
только для чтения, флаги прокси и публичного IP.

## Закреплённая зависимость

`go.mod` подменяет `github.com/anacrolix/torrent` на `github.com/tsynik/torrent v1.2.34`
(и `anacrolix/upnp` на `tsynik/upnp`) — так же, как это делает TorrServer: код кэша
написан под API хранилища этого форка. Переход на основной anacrolix потребует
переписать `torrstor`.
