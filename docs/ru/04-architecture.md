## Запуск процесса (`backend/main.go`)

Порядок запуска:

1. `config.Load()` читает переменные окружения (`PORT`, `DATA_DIR`, `TMDB_KEY`,
   `LOG_PATH`, `DEFINITIONS_URL`) и создаёт каталог данных.
2. Пакет настроек торрент-движка открывает свой bbolt-файл `config.db` в каталоге данных
   (`tssettings.InitSets`): настройки движка и сохранённые торренты.
3. `store.Open` открывает `plenka.db` для собственных данных сервера: настройки
   приложения, состояние и cookies трекеров, состояние обновления определений, история
   просмотров.
4. Создаются сервисы: `appconfig`, `tmdb`, `history`, `indexers`. Менеджер трекеров
   загружает определения из `$DATA_DIR/definitions/`, а `StartDefinitionsUpdate` скачивает
   свежий набор в фоне.
5. `torrents.IndexerLinkResolver = idx.ResolveLink` — позднее связывание, через которое
   API торрентов разрешает ссылки `/api/indexers/{id}/download?token=…` внутри процесса,
   не импортируя пакет трекеров.
6. Запускается BitTorrent-клиент (`torr.NewBTS().Connect()`).
7. `httpserver.New` собирает роутер gin с модулями (appconfig, tmdb, history, indexers,
   torrents), и запускается HTTP-сервер. По SIGINT/SIGTERM он корректно завершается,
   затем закрываются движок и обе базы.
8. `discovery.Listen` отвечает на поиск сервера в сети по UDP на том же номере порта
   (см. 31-rest-api, раздел 2). Ошибка привязки пишется в лог и не останавливает сервер.

## Поток данных: просмотр фильма

1. Клиент → `GET /api/tmdb/3/movie/{id}` (карточка) — проксируется с ключом, кэш 10 минут.
2. Клиент → `GET /api/search?q=…` — менеджер трекеров параллельно опрашивает все
   включённые трекеры с заданным таймаутом, убирает дубли и сортирует по сидам.
3. Клиент → `POST /api/torrents {"link":…}` — ссылка (magnet, URL .torrent, infohash или
   ссылка скачивания трекера) разрешается, торрент сохраняется и подключается к пирам.
4. Клиент опрашивает `GET /api/torrents/{hash}`, пока не придут `files`.
5. Плеер → `GET /api/stream/{hash}/{fileId}/{name}` — Range-запросы обслуживает читатель
   движка; куски впереди читателя получают приоритет (упреждающее чтение).
6. Клиент → `PUT /api/history` каждые 5 с с позицией.

## Хранение

| Файл | Владелец | Содержимое |
|---|---|---|
| `plenka.db` | `internal/store` | бакеты `config` (настройки приложения), `indexers` (включён, настройки, последняя ошибка), `indexers_cookies`, `indexers_meta` (ключ токенов скачивания, применённые умолчания по id, состояние обновления определений), `history` |
| `config.db` | `internal/torrserver/settings` | `Settings/BitTorr` (настройки движка), `Torrents/<hash>` |
| `definitions/` | `internal/indexers` | скачанные YAML-определения Cardigann; при каждом успешном обновлении заменяются целиком |
| каталог торрентов | движок | `TorrentsSavePath` (пусто → `DATA_DIR/torrents`): в `<hash>/keep/` — предзагруженные и скачанные целиком куски (всегда на диске, удаляются вместе с торрентом); `<hash>/<кусок>` — кэш воспроизведения при включённом «кэше на диске» |

Всё время хранится и отдаётся в UTC.
