# Структура фронтенда

`frontend/` — одностраничное приложение на Vue 3, которое выглядит и ведёт себя как
мобильное. Собирается Vite и встраивается в бинарник сервера, поэтому в продакшене оно
отдаётся с того же адреса, что и API, и все запросы идут по относительным URL.

Стек: Vue 3 (`<script setup lang="ts">`), vue-router, Pinia, строгий TypeScript, обычный
CSS на дизайн-токенах. Без UI-китов и CSS-фреймворков. Менеджер пакетов — **pnpm**.

| Скрипт | Что делает |
|---|---|
| `pnpm dev` | Vite на :5173; проксирует пути сервера `/api/*`, `/img/*` и `/health` на :8095 (адрес меняется через `PLENKA_SERVER`) |
| `pnpm build` | `vue-tsc` + `vite build` → `frontend/dist` (`make web` копирует его в `backend/web/dist`) |
| `pnpm test` | модульные тесты Vitest (happy-dom) рядом с кодом (`*.test.ts`) |
| `pnpm typecheck` | `vue-tsc --noEmit` |

## Структура каталогов

```
src/
  api/          http.ts (JSON-запросы, обработка {error}, таймауты, отмена) + файл на каждую часть
                сервера (info, tmdb, search, indexers, definitions, history, torrents, engine);
                типы ответов (camelCase) в types.ts
  stores/       Pinia: server (info + config), catalog, history, torrents, indexers (+ состояние
                определений трекеров), настройки движка, prefs (режим плеера), playback, toast, dialog
  composables/  useAsync, usePolling, useAddRelease, useClipboard, useMediaQuery,
                usePlayerTracks (выбор аудио и субтитров в плеере)
  utils/        format, files, media, releases, history, внешний плеер, sanitize,
                форма трекера, subtitles (разбор SRT/VTT/ASS), trailers, errors — чистые функции с тестами
  components/
    layout/     AppShell (KeepAlive для вкладок, анимации перехода), NavBar (нижние вкладки / боковая панель), AppBar
    ui/         UiButton, IconButton, Badge, StatusDot, Spinner, Skeleton, EmptyState,
                ErrorBanner, Segmented, Chip, Toggle, Sheet, ConfirmDialog, ToastHost,
                ProgressLine, CopyField, Icon (SVG-пути в icons.ts)
    media/      PosterCard, MediaRow, MediaGrid, BackdropCard, NetImage, ReleaseList,
                ReleaseTile, TorrentCard, PieceMap, ExternalSheet, PlayChooser, TracksPanel
    prefs/      вкладки настроек: PrefsGeneral, PrefsCatalog, PrefsTrackers, PrefsEngine
  views/        по компоненту на экран
  styles/       tokens.css, fonts.css, base.css
  i18n/         все тексты интерфейса: en.ts (шаблон), ru.ts (те же ключи), index.ts —
                `msg` на текущем языке; по умолчанию язык браузера, иначе английский;
                Настройки → Язык сохраняет `plenka.language` и перезагружает страницу
```

Данные идут `api/` → `stores/` → экраны и компоненты. Экраны не вызывают `fetch`
напрямую; после изменения стор обновляет состояние из ответа, а не перезагружает список.

## Экраны

| Маршрут | Экран |
|---|---|
| `/` (вкладка) | Главная: «Продолжить просмотр» из `/api/history`, шесть подборок TMDB |
| `/search` (вкладка) | Мультипоиск TMDB; `?mode=trackers` ищет сразу через `/api/search` |
| `/downloads` (вкладка) | Торренты в движке (`/api/torrents`): статус, скорость, пиры, время добавления, выгрузка/удаление, добавление по ссылке или файлом `.torrent`, карта кусков кэша, предзагрузка последнего просмотренного (иначе первого) видео, «Загрузить целиком» / отмена в окне торрента (прогресс на карточке) |
| `/prefs/:section?` (вкладка) | Настройки, разбитые на вкладки (сегментированный переключатель; вкладка хранится в URL, переключение заменяет запись истории): `/prefs` «Основные» — состояние сервера, язык интерфейса, режим плеера, версия приложения; `/prefs/catalog` «Каталог и поиск» — ключ TMDB (каталог запрашивается на языке интерфейса: `language=en-US` / `ru-RU` в каждом запросе `/api/tmdb`); `/prefs/trackers` «Трекеры» — таймаут поиска по трекерам и адрес FlareSolverr, блок «Определения трекеров» (число, время последнего обновления, источник, ошибка последнего обновления, кнопка «Обновить определения»), поиск трекера, фильтры, включение; `/prefs/engine` «Торрент-движок» — `/api/engine/settings`, сброс к умолчаниям. Старые ссылки `/indexers` и `/indexers/:id` перенаправляются сюда |
| `/movie/:id`, `/tv/:id` | Карточка фильма или сериала; «Смотреть» спрашивает, что смотреть: торренты (раздачи) или трейлеры |
| `/trailers/:type/:id` | Видео с YouTube из TMDB (`/videos` на настроенном языке, затем `en-US`; сначала трейлеры, новые выше); по нажатию видео играет во встроенном плеере YouTube, есть ссылка «Открыть на YouTube» |
| `/releases/:type/:id` | Раздачи для фильма: правка запроса, сортировка, фильтр качества, статус по трекерам |
| `/files/:hash?resume=&browse=1` | Ожидание списка файлов, фильтр видео, автозапуск единственного файла или продолжение. С `browse=1` (кнопки «Файлы» на вкладке «Торренты») показывает все файлы раздачи и ничего не запускает. У каждого видео есть кнопка предзагрузки (`POST /api/torrents/{hash}/preload`); прогресс предзагрузки виден под строкой статуса |
| `/player/:hash/:fileId` | HTML5-плеер со своими контролами, продолжением, сохранением позиции, следующей серией, панелью аудио и субтитров и запасным внешним плеером |
| `/prefs/trackers/:id` | Форма настроек трекера, построенная по его определению; сохранение и проверка |

Пути SPA не должны совпадать с путями сервера (`/api`, `/img`, `/health`). На любой
другой неизвестный GET-путь сервер отдаёт `index.html`.

## Поведение

- На телефоне — нижняя панель вкладок, от 840 px — боковая навигация. Вложенные экраны
  въезжают сбоку, переключение вкладок без анимации, вкладки сохраняют состояние и прокрутку.
- Браузеры не умеют играть многие файлы MKV/AC3/DTS. При ошибке воспроизведения или по
  кнопке «Внешний плеер» плеер предлагает: скопировать ссылку на поток, плейлист M3U,
  Android `intent:` для VLC или любого видеоплеера и `vlc-x-callback` на iOS. Источник
  `<video>` и ссылки — `/api/stream/{hash}/{fileId}/{имя файла в URL-кодировке}`; плейлисты —
  `/api/torrents/{hash}/playlist.m3u?file={id}` (один файл) и
  `/api/torrents/{hash}/playlist.m3u` (весь торрент).
- Аудио и субтитры: панель плеера показывает аудиодорожки, которые браузер видит внутри
  файла (`HTMLMediaElement.audioTracks`: Safari; другие браузеры играют только дорожку по
  умолчанию, и панель об этом пишет), текстовые дорожки, которые он видит, и отдельные файлы
  раздачи: субтитры (`srt`, `vtt`, `ass`, `ssa`; читаются как UTF-8, иначе Windows-1251, и
  добавляются как `TextTrack`) и аудио (`mka`, `ac3`, `eac3`, `dts`, `aac`, `flac`, `mp3`,
  `m4a`, `opus`, `ogg`, `wav`). Отдельный аудиофайл играет в скрытом `<audio>`,
  синхронизированном с заглушённым видео; файлы с именем видео идут первыми.
- Нет изображения: если у видеофайла есть звук, а картинка 0×0 (браузер не декодирует
  видео HEVC 10 бит, HDR10+ или Dolby Vision), плеер ставит паузу и предлагает внешний
  плеер или «Только звук».
- Определения трекеров: сервер скачивает их при старте, и список заполняется, когда загрузка
  закончится. Пока сервер сообщает `updating`, экран трекеров каждые 3 с запрашивает
  `GET /api/definitions` и по окончании обновления перезагружает список. Кнопка «Обновить
  определения» вызывает `POST /api/definitions/update` (таймаут 150 с, спиннер на время
  запроса) и затем перезагружает список; неудачное обновление показывает ошибку, прежний
  набор остаётся. Если определений нет и в списке только встроенные индексаторы (Knaben и
  собственное определение RuTracker.org), экран показывает
  пустое состояние: объясняет, что определения загружаются, или предлагает кнопку.
- В поле торрента `data` лежит снимок карточки TMDB в JSON (в той же форме, что `media` в
  истории), поэтому экраны файлов и плеера переживают перезагрузку страницы.
- Удаление из «Продолжить просмотр» стирает историю всех торрентов этого фильма
  (`DELETE /api/history/{hash}` для каждого), чтобы на его место не встала прошлая серия.
- Время с сервера приходит в UTC и показывается в часовом поясе браузера в формате
  `YYYY-MM-DD HH:MM:SS`.
- Манифест PWA и иконка позволяют «Добавить на главный экран»; service worker нет,
  поэтому запросы к API и видео никогда не кэшируются.
