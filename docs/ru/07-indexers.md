# Поиск по трекерам (индексаторы)

`backend/internal/indexers/` — модуль поиска по трекерам: собственная реализация
формата YAML-определений Cardigann, собственные определения, нативный мета-поиск Knaben, управление
индексаторами и нативный API поиска (`/api/search`, `/api/indexers/*`,
`/api/definitions*`, см. [31-rest-api](31-rest-api.md) §1.4–1.6). API, совместимого с
Jackett, нет.

## Скачиваемые определения

В бинарнике нет сторонних определений трекеров (только собственные, см.
[Собственные определения](#собственные-определения)). Они скачиваются во время работы:

- Источник: переменная `DEFINITIONS_URL` (`internal/config`), по умолчанию
  `https://codeload.github.com/Jackett/Jackett/tar.gz/refs/heads/master` (~5 МБ).
- `defsource.go` распаковывает `.tar.gz` потоком (архив целиком в память не читается)
  и берёт каждый обычный файл `*.yml`, родительский каталог которого называется
  `Definitions` (в Jackett это `src/Jackett.Common/Definitions/`; в
  `Indexers/Definitions/` лежат только `.cs`). Скрытые имена, файлы больше 2 МБ и более
  5000 файлов отклоняются; таймаут скачивания — 2 минуты.
- Файлы пишутся во временный каталог внутри `$DATA_DIR`, который затем заменяет
  `$DATA_DIR/definitions/` (переименованием; прерванная замена исправляется при
  следующем запуске).
- Результат хранится в `plenka.db`, бакет `indexers_meta`, ключ `definitions`:
  `updatedAt` (UTC, последнее успешное обновление) и `lastError` (последняя ошибка,
  сбрасывается при успехе).
- При запуске менеджер загружает то, что лежит на диске (ноль определений — нормально,
  Knaben работает и так), и запускает обновление в фоне (`StartDefinitionsUpdate`,
  подключено в `main.go`). `POST /api/definitions/update` запускает обновление по
  запросу; одновременные запросы присоединяются к уже идущему. Неудачное скачивание или
  архив без определений оставляют прежний набор и записывают `lastError` (эндпоинт
  отвечает `502`).
- После успешного обновления все индексаторы перезагружаются. Включённость и настройки
  хранятся по id индексатора, поэтому сохраняются; исчезнувший id скрывается и
  возвращается со своими настройками. По `replaces` из определения подхватывается
  состояние, сохранённое под старым id.
- Каждый файл при загрузке разбирается и проверяется (`check.go`): компилируются
  шаблоны, CSS/JSON-селекторы, регулярные выражения и имена фильтров. Файлы с
  некорректным YAML или без id/links/search пропускаются с записью в лог. Определения с
  проблемами показываются в списке, но не запускаются: их `lastError` —
  `unsupported definition: …`. В памяти остаются только метаданные (название, тип,
  адреса, настройки, категории) — около 1,5 МБ на 586 определений; полное определение
  разбирается заново при первом использовании индексатора.

Все индексаторы, включая встроенные, изначально выключены: пользователь включает трекеры
в настройках трекеров (**Настройки → Трекеры** в веб-интерфейсе). До этого поиск отвечает
без индексаторов, и клиенты сообщают об этом.

С определениями Jackett (586 файлов) загружаются все 586; проверки проходят 584. Два
оставшихся используют селекторы вне CSS (`:has(~ …)` и два склеенных составных
селектора).

## Собственные определения

В `backend/definitions/` лежат собственные определения Plenka в том же YAML-формате. Они
встроены в бинарник (`definitions.FS`), поэтому есть в списке ещё до скачивания и
загружаются без сети. Менеджер читает их первыми, а скачанный набор — после: собственное
определение перекрывает скачанное с тем же id (в лог пишется
`own definition overrides a downloaded one`). В `GET /api/definitions` → `count` они не
входят.

- **RuTracker.org** (`rutracker.yml`, id `rutracker`; в скачиваемом наборе есть только
  `rutracker-ru` для другого сайта rutracker.ru). Нужна учётная запись (`username`,
  `password`); адрес сайта можно переключить на зеркала `rutracker.net` / `rutracker.nl`.
  Вход: POST `forum/login.php` (windows-1251), проверка по `#logged-in-username` на
  `forum/index.php`; капча (`cap_sid`) или сообщение сайта об ошибке возвращаются как
  ошибка. Поиск: `forum/tracker.php?nm=…`; строки без ссылки на скачивание (закрытые или
  непроверенные раздачи) пропускаются; `.torrent` скачивается с `forum/dl.php?t=…` через
  сессию. Форумов на сайте сотни, поэтому категория определяется по словам в названии
  форума фильтрами `re_replace` (фильм/кино, сериал, аниме, HD/UHD/DVD, музык, аудиокниг,
  игр, …).

Нативный индексатор **Knaben** (`knaben.go`, публичный мета-поиск с JSON API) живёт в
коде.

## Движок

| Область | Файлы | Что делает |
|---|---|---|
| Модель | `def.go` | модель YAML; порядок сохраняется для inputs, полей, `case` и вариантов select; принимается экранирование `\/`; без блока `settings` — логин и пароль |
| Шаблоны | `tmpl.go` | `{{ .Config.x }}` (в именах допустим `-`), `.Keywords`, `.Query.*`, `.Categories`, `.Result.*`, `.DownloadUri.*`, `.Today.Year`, `.True`/`.False`; `if`/`else if`/`else`/`end`, `range` (в т. ч. `$i, $e :=`), `and`, `or`, `not`, `eq`, `ne`, `join`, `re_replace`; значения, подставленные в пути и поля `$raw`, URL-кодируются в кодировке сайта |
| Вход | `auth.go` | методы `post`, `get`, `form` (заполняет форму страницы: скрытые поля, отмеченные флажки, первая кнопка submit, `selectors: true`), `cookie`, `oneurl`; `inputs`, `selectorinputs`, `getselectorinputs`, `cookies`, `headers`, `error` (с `message`), `test` (редирект или отсутствие селектора = не вошли) |
| Поиск | `cardigann.go` | `paths` (метод, поля с `inheritinputs`, `categories` с `!`, `followredirect`, `response` html/json/xml, `noResultsMessage`), `keywordsfilters`, `preprocessingfilters`, `headers`, `error`, `allowEmptyInputs`; строки с `after`, `dateheaders`, `andmatch`, `count`, `attribute`/`multiple`/`missingAttributeEqualsNoResults`; поля в порядке определения с `selector`/`attribute`/`text`/`remove`/`case`/`optional`/`default`/`filters` |
| Селекторы | `dom.go`, `jsonsel.go` | HTML через `x/net/html` + cascadia (аргументы `:contains(…)` и значения атрибутов без кавычек берутся в кавычки, поддерживается `:scope`); XML (ленты RSS/Torznab) превращается в такое же дерево узлов; JSON-пути `a.b`, `x[0]`, `$`, родитель `..`, `:has()`, `:not()`, `:contains()` |
| Фильтры | `filterchain.go`, `timeparse.go` | querystring, prepend, append, replace, re_replace, regexp (синтаксис .NET через regexp2; блоки вида `\p{IsCyrillic}` переписываются в диапазоны), split, trim, tolower, toupper, urlencode/urldecode, htmlencode/htmldecode, base64encode/base64decode, diacritics, validfilename, validate, jsonjoinarray, dateparse/timeparse (строки формата .NET сопоставляются по токенам), timeago/reltime, fuzzytime (в т. ч. `UK`), strdump/hexdump (отладочный лог); аргументы могут быть шаблонами |
| Значения | `values.go`, `newznab.go` | размеры (`1.5 GB`, `1.024,4 MB`, `700 МБ`), числа, даты, id IMDb; таблица категорий Newznab и сопоставление (запрос 2000 находит 2040; результат получает и родительскую категорию); для публичных и полуприватных трекеров magnet строится из `infohash` |
| Скачивание | `fetch.go` | блок `download`: `before` (путь или `pathselector`, метод, поля, `queryseparator`), `selectors` по порядку (`usebeforeresponse`), `infohash` → magnet; иначе — сама ссылка; редиректы на `magnet:` отслеживаются |
| HTTP | `session.go` | сессия на индексатор: cookies в пределах домена трекера (хранятся в `indexers_cookies`), кодировка сайта (`windows-1251` …) для запросов и ответов, `requestDelay`, ручные редиректы, лимит ответа 16 МБ, `certificates` (SHA-1 для неисправных сертификатов), настройка `useragent` |

Игнорируются ключи: `followredirect` верхнего уровня (автообновление адреса сайта) и
`testlinktorrent`. Информационные поля, постеры и id (`poster`, `imdbid`, `genre`,
`description`, …) отбрасываются, если селектор ничего не нашёл, как и предписывает
формат; отсутствие обязательного поля пропускает строку.

Проверки Cloudflare проходят через [FlareSolverr](https://github.com/FlareSolverr/FlareSolverr),
если задан его адрес (`flareSolverrUrl`, **Настройки → Адрес FlareSolverr**), как в
Jackett и Prowlarr. Если ответ — проверка Cloudflare (`Cf-Mitigated: challenge` или
403/503/429 от `Server: cloudflare` со страницей проверки), сессия отправляет
`request.get` этого адреса в `<flareSolverrUrl>/v1` (`flaresolverr.go`, до 60 с, но не
дольше таймаута поиска), забирает полученные cookies домена трекера (`cf_clearance`,
сохраняется вместе с сессией) и User-Agent браузера и один раз повторяет запрос. Без
FlareSolverr ошибка — `the site is behind a Cloudflare challenge: set the FlareSolverr
address…`; проверка и после решения сообщается отдельной ошибкой. User-Agent хранится
только в памяти, поэтому после перезапуска первый запрос решается заново. FlareSolverr
может думать 10–30 с; если проверки не укладываются, увеличьте таймаут поиска.

Не поддерживаются, с понятной ошибкой вместо падения: формы входа с капчей (если трекер
позволяет, можно использовать вход по cookie).

## Менеджер

`manager.go` хранит состояние трекеров в `plenka.db` (`indexers`: включён, настройки,
последняя ошибка и время проверки; `indexers_cookies`; `indexers_meta`). Поиск
параллельно (по 16) опрашивает выбранные трекеры с заданным таймаутом
(`searchTimeoutSec`, по умолчанию 30 с), пропускает трекеры без подходящей категории,
запоминает статус каждого, объединяет результаты по infoHash (иначе по
названию+размеру) и сортирует по сидам. Трекеры с незаполненными обязательными
настройками (поля-пароли и настройки вроде `username`, `cookie`, `apikey`) отвечают
`indexer is not configured`. Изменение настроек пересоздаёт движок и сбрасывает
сохранённую сессию.

## Токены скачивания

У результатов без magnet `link = /api/indexers/{id}/download?token=…`. Токен — JSON с
целевым URL в base64url, подписанный HMAC-SHA256 по id трекера и случайному ключу из
`indexers_meta` (`tokenKey`). Его нельзя подделать под произвольный URL, и он работает
только через выдавший его трекер. `Manager.ResolveLink` (ссылка → байты `.torrent` или
magnet) обслуживает и HTTP-эндпоинт, и торрент-движок, который получает его через
позднее связывание в `main.go` (см. [08-torrent-engine](08-torrent-engine.md)).

## Тесты

`go test ./internal/indexers/` работает без сети: серверы `httptest` отдают вымышленные
страницы трекеров, JSON и RSS для встроенных в тесты определений (формы входа, сессии,
блоки скачивания, кодировки, скачивание и обновление определений, HTTP API).

- `PLENKA_DEFINITIONS_DIR=<каталог> go test -run TestAllDefinitions -v ./internal/indexers/`
  загружает все `*.yml` из каталога (например, скачанный `$DATA_DIR/definitions`),
  сообщает, сколько загрузилось и прошло проверки, и запускает поиск каждым
  определением на локальной заглушке (без сети), чтобы поймать ошибки шаблонов.
- `go test -tags live -run TestLive -v ./internal/indexers/` скачивает определения и
  ищет на настоящих трекерах (переменные `PLENKA_LIVE_INDEXERS`, `PLENKA_LIVE_QUERY`,
  `DEFINITIONS_URL`).
